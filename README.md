# wolt-reg-bot

Telegram-бот для ручной регистрации в Wolt и Google: **почта → письмо со ссылкой → виртуальный номер → SMS-код**. Формы, OAuth и капчу проходит человек; бот обеспечивает почту, номера и доставку результатов.

Репозиторий содержит публичную версию рабочего кода: личные параметры заменены настройками окружения. Баз, ключей и пользовательских данных здесь нет. Push в GitHub **не выкладывает код на VPS автоматически**. Не путать с [wolt-easy](https://github.com/r1nnegann/wolt-easy) — это другой проект.

## Сценарии

В меню `/start` → «Начать регистрацию»:

- **Wolt: почта + SMS (KZ +7)** — случайный ящик Mail.tm, ожидание письма Wolt, ссылка, затем номер Казахстана и SMS.
- **Wolt: почта + SMS (HeroSMS)** — выбор домена из живого каталога для `wolt.com`, подтверждение покупки почтовой активации, ожидание письма, доставка ссылки, затем номер Казахстана и SMS.
- **Wolt: только SMS (KZ +7)** — покупка номера без создания почты.
- **Gmail (выбор страны)** — живой список стран с ценой и наличием, затем номер и SMS. Бот не создаёт Google-аккаунт вместо человека.
- **Google → Wolt SMS** — после кода Google появляется кнопка перехода к Wolt SMS; дополнительный почтовый ящик не создаётся.

Номера отображаются полностью, **без маски и без международного префикса**, чтобы их можно было вставить в форму. У Wolt используется HeroSMS `rr` / Казахстан `2`; у Google — `go` и выбранная страна (`gm` — не Gmail).

## Что нового относительно первой публичной версии

- Отдельная **почтовая цепочка через HeroSMS REST API**, без удаления старого режима Mail.tm. Домены с наличием показываются по возрастанию цены, по 8 на странице, с ценой в USD и остатком; список можно обновить.
- Поддержка `message: null` и `value: null` у новой почтовой активации в статусе `WAIT`. После `SUCCESS` ссылка извлекается из HTML-письма в `message`.
- Успешные email-ответы HTTP `200`/`201` принимаются только после проверки полного ресурса; неверный ID, сайт, домен, валюта или цена не считаются покупкой.
- **Смена номера сразу**: новый покупается без ожидания отмены старого. Отмены сохраняются в SQLite и выполняются в фоне не раньше чем через 120 секунд.
- Именованные админские HeroSMS-ключи, назначение ключей пользователям, собственные ключи и сохранение исходного ключа купленной активации.
- Личная и админская статистика по периодам, управление пользователями, одиночное и массовое удаление почт с подтверждением.
- Защита повторных подтверждений, восстановления после рестарта, доставки длинных ссылок и удаления почты во время незавершённой покупки SMS.

## Как работает почта HeroSMS → Wolt → SMS

```text
Выбор режима почты HeroSMS
  → GET /api/v1/emails/domains?site=wolt.com: доступные домены, цены USD, наличие
  → выбор домена (без покупки)
  → цена выбранной почты, цена SMS KZ, наличие и баланс
  → явное подтверждение покупки
  → POST HeroSMS /api/v1/emails: site=wolt.com, domain=<выбранный домен>
  → адрес сохраняется в SQLite и появляется в Telegram
  → человек вводит email в Wolt
  → проверка существующей активации каждые 5 секунд
  → письмо Wolt → сохранение и доставка ссылки
  → только после доставки ссылки: покупка rr/KZ номера
  → человек вводит номер → SMS через webhook или polling
```

**Это активация почты для конкретного сайта, не постоянный аккаунт с паролем.** Бесплатная проверка сохранённой почты читает исходный ID с ключом покупки, независимо от текущего каталога доменов. Платный `reorder` автоматически не вызывается; новое письмо, повторный вход и бессрочный доступ к ящику не гарантируются.

Фиксированного списка доменов и подмены отсутствующего домена на Outlook нет. Вход в режим, выбор, страницы и обновление ничего не покупают. «Обновить оценку» сохраняет выбранный домен; «Сменить домен» возвращает в каталог и отменяет прежнее подтверждение. Кнопки привязаны к серверному снимку и случайному токену: старые подтверждения после обновления, смены домена, сервиса или отмены не списывают деньги.

Перед покупкой показываются актуальные предложения и оценка суммы почты + SMS с запасом к SMS-цене. Перед списанием повторно проверяются именно выбранный домен, остаток, цена, баланс и назначение ключа. Рост цены, исчезновение предложения или смена ключа требуют нового подтверждения; другой домен автоматически не покупается. Домен в ответе покупки проверяется на точное совпадение, не по суффиксу. Цена номера может измениться за время ожидания письма; общая оценка не является фиксированным тарифом. API покупки почты не даёт серверного price-cap/idempotency-поля — его здесь не выдумывают.

Письмо ожидается до **300 секунд**. Таймаут сохраняет запись для повторной проверки и не означает подтверждённый возврат. Ссылки длиннее лимита Telegram CopyTextButton в 256 символов доставляются URL-кнопкой и HTML-ссылкой.

### Неопределённый результат покупки

Если HTTP-ответ потерялся, деньги уже могли быть списаны. До POST в `email_purchase_intents` сохраняются выбранный `domain`, ключ и `uncertain`, и бот **не повторяет платный запрос автоматически**, в том числе после рестарта. Добавочная миграция старых intents устанавливает `domain=outlook.com`, не снимая блокировку `uncertain`. Требуется ручная сверка HeroSMS. Нельзя угадывать принадлежность по последней покупке общего ключа или просто удалять предохранитель и покупать заново.

Если пользователь завершает такую покупку вручную, её нельзя автоматически продолжать, отменять или запускать для неё SMS. Локальная отметка о ручной обработке допустима только после проверки точного ID, ключа и времени покупки.

## SMS, отмены и сохранённые данные

- SMS ожидается **600 секунд**; запрос повтора отправляется после 120 секунд. Polling — каждые 7 секунд.
- Защищённый HeroSMS webhook ускоряет доставку; polling остаётся резервом. Повтор webhook атомарно отсеивается в SQLite.
- Webhook автоматически отправляет HeroSMS `setStatus(6)`. В polling-ветке получение кода фиксируется локально, а внешнее завершение выполняет кнопка «Завершить».
- «Сменить номер» сразу покупает замену и сохраняет отмену прежнего номера в `pending_number_actions`. Ключ каждой покупки сохраняется отдельно от текущего назначения пользователя.
- Отмена номера подтверждается только удалённым `STATUS_CANCEL`. Ошибки, ранний отказ и неподтверждённые ответы повторяются ограниченно; возврат денег заранее не обещается. Для просмотра и повторов есть «Отмены номеров».
- «Мои почты» различает Mail.tm и HeroSMS и показывает фактический домен. Нельзя отправлять почтовую активацию HeroSMS в Mail.tm login/delete. Активный или неподтверждённый номер не позволяет удалить нужную для восстановления запись.
- Пользователи отключаются без удаления истории. Статистика успешных SMS считает записанную стоимость номеров, **не прибыль, не баланс и не стоимость почтовых активаций**.
- SQLite работает в WAL. ID почт, ключи активаций, история и очередь отмен сохраняются; **MemoryStorage FSM не сохраняется** — незавершённые Wolt-сценарии восстанавливаются через кнопки продолжения/повтора.

## Стек и схема

Python 3.12, aiogram 3, httpx, aiohttp, python-dotenv, SQLite. Основная логика намеренно остаётся в одном `bot.py`.

```text
Telegram long polling ── bot.py ── Mail.tm REST (почта и письма)
                            ├──── HeroSMS legacy (цены, номера, SMS)
                            ├──── HeroSMS REST (почтовые активации выбранного домена)
                            └──── SQLite (данные, ключи, intents, отмены, UI)
                                  ▲
HeroSMS → HTTPS /hooks/herosms/<secret> → nginx → aiohttp listener
```

Основные таблицы: `users`, `admin_keys`, `activations`, `accounts`, `email_purchase_intents`, `pending_number_actions`, `logs`, `ui_messages`. Миграции добавочные и повторяемые; не заменяют существующую базу. Файл БД содержит секреты, поэтому требует ограниченных прав и защищённого резервного копирования.

## Быстрый старт

Понадобятся Telegram bot token, свой Telegram ID и HeroSMS API key. Mail.tm отдельного API-ключа не требует.

```bash
git clone https://github.com/r1nnegann/wolt-reg-bot.git
cd wolt-reg-bot
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
```

Заполни `.env` своими значениями:

```dotenv
BOT_TOKEN=your_telegram_bot_token
ADMIN_ID=your_numeric_telegram_id
ADMIN_NAME=Admin
HERO_KEY=your_herosms_api_key
```

```bash
python bot.py
```

`ADMIN_ID` должен быть положительным числовым ID. Администратор создаётся при инициализации БД; новые пользователи добавляются при `/start`, но для покупок им нужен собственный или назначенный админский HeroSMS-ключ.

### Настройки

- `BOT_TOKEN`, `ADMIN_ID`, `HERO_KEY` — обязательная конфигурация запуска.
- `ADMIN_NAME` — имя начального администратора, по умолчанию `Admin`.
- `SMS_BOT_ENV` — путь к dotenv, по умолчанию `.env` рядом с `bot.py`.
- `SMS_BOT_DB` — путь к SQLite, по умолчанию `data/bot.db` рядом с `bot.py`.
- `HERO_WEBHOOK_TOKEN` — секрет пути webhook; пустое значение отключает listener, но не polling.
- `HERO_WEBHOOK_HOST` — адрес listener, по умолчанию `127.0.0.1`.
- `HERO_WEBHOOK_PORT` — порт listener, по умолчанию `18091`.

Ключи пула и пользовательские ключи хранятся в SQLite. Назначенный именованный ключ имеет приоритет: состояние одного `.env`-ключа не показывает доступность всех пользователей.

### Docker

```bash
docker compose up -d --build
docker compose logs -f
```

Перед запуском заполни `.env`. База сохраняется в `./data`, порт публикуется только на `127.0.0.1:18091`; внутри контейнера listener использует `0.0.0.0`. Секреты в образ не копируются. Не запускай контейнер одновременно с другим polling-процессом на том же токене.

### Webhook и systemd

- Пример nginx: [`deploy/nginx-herosms.conf.example`](deploy/nginx-herosms.conf.example). Публикуй только точный секретный путь, а не весь listener.
- Шаблон systemd: [`deploy/sms-bot.service`](deploy/sms-bot.service). Он рассчитан на отдельного системного пользователя и установку в `/opt/wolt-reg-bot`.
- У пользователя сервиса должны быть права на каталог базы и dotenv. Не помещай ключи в unit или git; используй `.env` с правами `0600`.
- **Два процесса с одним `BOT_TOKEN` вызовут Telegram `409 Conflict`.** Перед переключением способа запуска останови прежний экземпляр штатно и сохрани базу.

## Тесты и CI

```bash
python scripts/run_tests.py
python scripts/run_tests.py --pattern test_outlook_nullable_response.py
python scripts/run_tests.py --pattern test_hero_domains.py
python -m compileall -q bot.py tests scripts
```

Тестовый runner подставляет синтетическую конфигурацию **до импорта бота**, создаёт и инициализирует временную SQLite, блокирует доступ к реальной базе и внешней сети. Локальный ephemeral aiohttp-сервер разрешён для webhook-тестов. Боевые токены, покупки, отмены и регистрация на Wolt/Google не нужны.

Покрываются каталог и пагинация доменов, бесплатная навигация, точный домен POST/ответа, устаревшие и поддельные callbacks, смена домена/сервиса/ключа, изменение цены и наличия, обе почтовые цепочки, nullable-ответы HeroSMS, неопределённость покупки, доставка ссылки до покупки SMS, восстановление, ключи, статистика, очередь отмен, удаление и гонки при сетевых ожиданиях. Успех замоканных тестов **не означает проверку реального списания, возврата или полного платного цикла**.

GitHub Actions запускает тесты и проверку синтаксиса на push/PR. Автоматического деплоя нет.

## Безопасность и ограничения

См. [`SECURITY.md`](SECURITY.md). Не публикуй `.env`, базы, их резервные копии, почтовые пароли, SMS-коды или ссылки входа. В диагностике покупки остаются только HTTP-статус, типы фиксированных полей, этап и класс ошибки, не тело ответа.

Бот не обходит капчу, антифрод и ограничения Wolt/Google. Использование сторонних номеров и почтовых активаций не гарантирует успешную регистрацию или сохранение доступа. Пользователь отвечает за соблюдение правил сервисов. Это не официальный продукт Wolt, Google, Telegram, HeroSMS или Mail.tm.
